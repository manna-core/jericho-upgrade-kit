# Customer Memory Rules

Use before building account memory, relationship intelligence, customer briefs, or AI recall.

## Allowed memory

- Company name and basic account metadata.
- Contacts and roles.
- Explicit preferences shared for business use.
- Past meetings and action items.
- Products purchased or evaluated.
- Support issues.
- Follow-up commitments.
- Risk notes tied to business relationship.

## Sensitive memory

Requires clear purpose and careful access control:

- employee performance notes,
- internal company strategy,
- contract terms,
- pricing concessions,
- private emails,
- meeting transcripts,
- documents uploaded by customers.

## Prohibited memory by default

- API keys or passwords,
- raw tokens,
- payment data,
- secrets from customer systems,
- unrelated personal information,
- anything the product cannot explain why it stores.

## User controls

The system should support:

- correction,
- deletion or archive where appropriate,
- source trace,
- freshness label,
- role-based access.

## AI output rule

When AI uses customer memory, the UI should make clear whether the output is:

- sourced,
- inferred,
- stale,
- draft,
- verified by a human.
