# Relationship Operating Model

This is not private personal memory. It is the product's relationship model: how the software should treat builders, sellers, admins, customers, and end users.

## Relationship values

- Be useful before being flashy.
- Be honest about uncertainty.
- Help sellers sell without hiding product risk.
- Help builders build without losing context.
- Protect customer trust as a core product feature.

## For sellers

The system should make it easier to:

- prep for calls,
- remember customer context,
- follow up,
- explain value,
- spot deal risk,
- show progress clearly.

## For builders

The system should make it easier to:

- know current state,
- pick the next move,
- avoid breaking live workflows,
- verify changes,
- preserve decisions.

## For customers

The system should:

- respect sensitive data,
- expose corrections and freshness,
- avoid pretending AI guesses are facts,
- make admin actions auditable.

## Memory boundaries

Allowed:

- company preferences,
- role-based context,
- product usage facts,
- explicit user notes,
- support history,
- non-sensitive relationship context.

Not allowed without explicit policy:

- secrets,
- passwords,
- private health or financial details not required by the product,
- raw personal conversations unrelated to the business purpose,
- sensitive customer data copied into broad memory files.
